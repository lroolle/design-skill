# Base materials

Open [the inspection index](index.html). Eight working standing exits,
one per recipe. They are not directions and
they are not screenshots to imitate. They make the protected behavior,
states, density, and responsive failure points concrete before a rolled
composition remakes the topology.

| Base | Mode | What is already real |
|---|---|---|
| [landing](landing.html) | persuade | offer, one action, product proof in the first viewport |
| [dashboard](dashboard.html) | operate | filterable population, outlier, selected-row detail |
| [docs](docs.html) | read | section tree, article, runnable request and response |
| [editorial](editorial.html) | read | issue hierarchy, article, evidence figure and source |
| [portfolio](portfolio.html) | experience | work first, project rail, project and business actions |
| [app-shell](app-shell.html) | operate | object tree, work surface, inspector, persistent status |
| [forms](forms.html) | operate | progress, labels, validation, review, reversible submit |
| [deck](deck.html) | persuade / read | one claim per slide, evidence, notes and slide order |

Open any file directly or serve this directory. `base.js` accepts
`?system=<name>` and swaps one of the seven system contracts. Every page
uses labelled sample data; replace all of it in a real build.

Copy the nearest base, then change its topology to the dealt composition.
If the final surface still has the base's region arrangement, record why
the standing exit won. Keeping it by inertia is template adoption.

`base.css` is the behavioral component contract shared by the fixtures:
actions, fields, tables, notices, empty states, tabs, rails, and overlays.
The system CSS supplies their material geometry through `--control-*`,
`--panel-*`, `--label-*`, `--row-*`, and `--rail-*` properties. That is the
minimum proof that a system is more than colors and fonts.
